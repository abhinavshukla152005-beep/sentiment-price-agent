# HK / KR social sentiment → next-day price

Retail chatter from two venues per exchange, turned into a daily feature panel, scored by a
walk-forward model, and rendered into a static report with tomorrow's directional calls and
the price levels that matter.

- **HKEX** — Tencent (0700.HK), Alibaba (9988.HK), Xiaomi (1810.HK), China Mobile (0941.HK),
  HKEX (0388.HK) — sources: **LIHKG** and **AAStocks**
- **KRX** — Samsung Electronics (005930.KS), SK Hynix (000660.KS), NAVER (035420.KS),
  Hyundai Motor (005380.KS), Kakao (035720.KS) — sources: **Naver 종목토론실** and **Blind**
- **News** — Exa `/search` (`category: news`) as a second, slower signal
- **Prices** — Yahoo Finance daily chart endpoint (no key)

```
Apify (LIHKG · AAStocks · Naver · Blind) ─┐
Exa /search (news headlines) ─────────────┼─→ normalise → lexicon sentiment → daily panel
Yahoo Finance (OHLCV) ────────────────────┘        │
                                                   ├─→ walk-forward GBM (expanding window)
                                                   ├─→ n+1 probability + expected return
                                                   └─→ reports/report.html  (self-contained)
```

## Run it

```bash
pip install -r requirements.txt

python -m src.run                 # offline: committed snapshot, no keys, no network
python -m src.run --mode live --days 10
python -m pytest -q               # 21 tests
```

`python -m src.run` prints the walk-forward metrics and the next-day calls, then writes
`reports/report.html`, `reports/predictions.csv` and `reports/panel.csv`.

## Live mode

Live mode is the real pipeline: Apify for the four retail venues, Exa for news, Yahoo for
bars. Copy `.env.example` to `.env` and fill both free-tier keys, then export them:

```bash
export APIFY_TOKEN=...        # PowerShell: $env:APIFY_TOKEN="..."
export EXA_API_KEY=...
python -m src.run --mode live --days 10
```

| Key | Where it comes from | Used for |
| --- | --- | --- |
| `APIFY_TOKEN` | Apify Console → Settings → API tokens (free plan, no card) | one crawl per asset per venue |
| `EXA_API_KEY` | exa.ai dashboard (free tier) | `/search` news per asset |

Actors driven (ids are in `src/config.py`):

- `apify/website-content-crawler` — LIHKG search, AAStocks comment pages, Naver board, Blind
  search. Payload: `playwright:adaptive`, `maxCrawlPages: 4`, `saveMarkdown: true`; the
  returned markdown is split into post-sized chunks, each with its own sentiment score.
- `apidojo/tweet-scraper` — optional cashtag chatter (`--tweets`).
- `apify/telegram-scraper` — optional channel traffic (`--telegram`).

Yahoo's endpoint needs no token, so prices work in both modes and cost nothing to verify.

## What the model actually does

Each row is one asset on one day. Features are the day's social aggregates (mention count,
engagement-weighted sentiment, bull/bear share, disagreement, per-venue counts), news
sentiment, and price state (1d/5d return, 10d volatility, range, gap, volume z-score, position
inside the trailing 20-day range). The target is the **next** close-to-close return.

Validation is walk-forward with an expanding window: for every test date the model is refit
on strictly earlier dates. No shuffling, no random split, no feature computed from a future
bar. A prediction for day D is always produced by a model that stopped learning at D−1.

Every score is reported next to two baselines — the majority-class rate and a zero-return
forecast — so "62% accuracy" can be read against "54.5% by always guessing up".

## Result (fixture snapshot, 40-day window)

| metric | value | baseline |
| --- | --- | --- |
| out-of-sample rows / dates | 310 / 34 | — |
| directional accuracy | **0.629** | 0.545 (majority) |
| balanced accuracy | 0.619 | 0.500 |
| AUC | 0.658 | 0.500 |
| MAE of next-day return | 0.0229 | 0.0209 (zero forecast) |
| corr(predicted, realised return) | 0.027 | — |

Read this honestly: **direction is learnable here, magnitude is not.** The classifier beats
the baseline by roughly 8 points; the return regressor is *worse* than predicting zero, which
is the normal outcome for daily equity returns with this little data. That is exactly why the
report quotes expected return next to a wide position band (LONG above 0.55, SHORT below 0.45)
instead of trading on it, and why the report labels the run as fixture mode.

### Why fixture mode exists, and why those numbers prove nothing about the market

The venues need a paid crawler run per asset; a reviewer should not have to fund that to see
the code work. So `data/fixtures/` ships a snapshot:

- `bars.csv` — **real** Yahoo Finance bars, frozen 2026-08-12 → 2026-11-10;
- `social.jsonl`, `news.jsonl` — **synthetic** posts and headlines, generated by
  `tools/make_fixtures.py`.

The synthetic text is not random: a day's dominant tone matches that ticker's *realised*
next-day sign 66% of the time. That plants a weak signal the harness can be tested against —
if walk-forward accuracy did not rise above the baseline on data with a known 66% signal, the
harness would be broken. It says nothing about live markets, where no such signal is known to
exist. Regenerate at any time with `python -m tools.make_fixtures --days 60`.

## Limitations

- Sentiment is a lexicon + negation/intensifier rules, not a transformer. It is inspectable
  (every score traces to matched tokens), free, and offline; it is also blind to sarcasm and
  to vocabulary outside the three languages it knows. `src/sentiment.py` is a single file, so
  swapping in a fine-tuned model is a local change.
- Crawler output is page text, not structured posts: engagement counts are only as good as
  what the markdown preserves, which is why the weighting is sub-linear and bounded.
- Ten assets over a 40-day window is a small sample. The confidence interval on a 0.629
  accuracy over 310 rows is wide; treat the number as "the pipeline is unbiased", not "there
  is a 63% edge".
- No transaction costs, no slippage, no intraday data, no shorting constraints, one run per
  mode. Positions are labels, not orders.
- The n+1 calls are for the next session after the last bar in the run; if you run this on a
  Friday, "next session" is Monday's open print, not a calendar day later.

## Layout

```
src/
  config.py          assets, per-exchange venues, actor ids, token accessors
  sentiment.py       lexicon scorer (en/zh/ko + emoji), negation, engagement weighting
  features.py        daily panel: social, news, price features, n+1 target
  model.py           walk-forward harness, metrics vs baselines, n+1 prediction
  report.py          inline-SVG HTML report, no JS, no CDN
  run.py             CLI: --mode fixture|live, --days, --tweets, --telegram
  ingest/
    prices.py        Yahoo chart endpoint
    apify.py         actor runs, dataset fetch, record normalisation
    exa.py           /search news
    fixtures.py      committed snapshot loader
tools/make_fixtures.py   regenerate bars + synthetic posts/news
tests/                   21 tests: scorer, feature leakage, walk-forward, fixtures
data/fixtures/           bars.csv, social.jsonl, news.jsonl
reports/                 report.html, predictions.csv, panel.csv
```

## Tests

`python -m pytest -q` covers the parts that are easy to get silently wrong:

- scorer polarity for English, Chinese and Korean, including negation and particles;
- **no lookahead** — features for earlier dates are unchanged when the last bar is altered;
- target equals the next close-to-close return, and the final bar has none;
- walk-forward recovers a planted signal and never tests on a training date;
- panel merges carry the right day's mentions, one row per asset per day;
- fixtures map to known assets and stay inside the bar window.
